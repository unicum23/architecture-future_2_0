# Технический радар «Будущее 2.0»

Радар построен по кольцам зрелости внедрения (по аналогии с ThoughtWorks Tech Radar): **Adopt** — применять по умолчанию, **Trial** — пилоты и ограниченный продакшен, **Assess** — изучение и POC, **Hold** — не расширять, планировать вывод.

Графическое представление [технического радара](tech-radar.png)

Дополнительно для каждой позиции указано: **текущее (as-is)** / **целевое (to-be)** и **бизнес-сценарии**.

---

## Кольцо Adopt (зафиксировать и масштабировать)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Облачная инфраструктура (IaaS/PaaS, управляемые сервисы) | To-be (ядро) | Масштабирование отчётности и пиковых нагрузок; геораспределение; снижение CAPEX на инфраструктуру |
| Разделение доменов и контракты данных (domain APIs, события) | To-be | Независимое развитие финтеха, ИИ и клиник; подключение новых партнёров без модификации монолита |
| Управление доступом и аудит (IAM, RBAC/ABAC, журналы) | Частично as-is → усилить to-be | Соответствие требованиям по медицинским и финансовым данным; снижение репутационных и регуляторных рисков |
| Lakehouse / облачное аналитическое хранилище | To-be | Оперативная подготовка отчётности и витрин; единые KPI без прямой нагрузки на операционные БД |

---

## Кольцо Trial (пилоты с измеримым результатом)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Портал самообслуживания (витрина данных, конструктор отчётов) | To-be | Самостоятельная работа аналитиков и бизнеса; ускорение принятия решений за счёт снижения очереди к IT |
| Семантический слой / метрики (dbt Semantic, Metric Layer и аналоги) | To-be | Согласованные показатели между BI и порталом; устранение расхождений в цифрах при управленческих обсуждениях |
| Платформа потоковых событий (Kafka / облачный аналог) | To-be (частичная замена паттернов ESB) | Асинхронная интеграция новых финтех-сервисов и доменов; слабая связанность компонентов |
| Data Mesh (принципы: продукты данных, федеративная модель) | To-be (эволюционный переход) | Масштабирование на новые бизнесы и партнёров без централизации логики в DWH |
| CDC и оркестрация (Airflow / Managed Workflow, Debezium и др.) | To-be | Актуальные витрины без ночных полных выгрузок; разгрузка легаси-DWH |

## Кольцо Assess (оценка, POC, выбор стека)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Замена / сужение роли Apache Camel (ESB) в пользу API Gateway + события | To-be | Time-to-market интеграций; снижение операционных затрат на сопровождение шины |
| MLOps для ИИ-сервисов (реестры моделей, воспроизводимость) | Частично as-is (Python) → усилить | Качество и предсказуемость ИИ-сервисов в клиническом контуре (в рамках политики) |
| Feature Store (при росте ML в продакшене) | Assess | Ускорение вывода моделей и согласованность признаков для медицинских сценариев |

---

## Кольцо Hold (не развивать; выводить)

| Технология / практика | As-is / To-be | Почему на Hold и какие сценарии страдают без миграции |
|----------------------|---------------|------------------------------------------------------|
| Расширение бизнес-логики в SQL Server 2008 DWH | As-is | Замедляет TTM; риски сопровождения и ИБ; блокирует независимое развитие доменов |
| Прямой тяжёлый ad-hoc из BI в монолитный DWH | As-is | Многочасовое построение отчётов; конкуренция с операционной нагрузкой; задержки в управленческих решениях |
| PowerBuilder как долгосрочная UI-стратегия | As-is | Высокая стоимость изменений; ограничения при найме; клинические сценарии привязаны к узкому стеку |

## Сводка: методологии

| Методология | Кольцо | Бизнес-сценарии |
|-------------|--------|-----------------|
| DevOps / GitOps в облаке | Trial → Adopt | Скорость релизов финтеха и платформы данных |
| FinOps (учёт и оптимизация облачных затрат) | Trial | Снижение расходов при росте объёмов данных и вычислений |
| Data Governance (владельцы данных, глоссарий, качество) | Trial | Доверие к отчётам; комплаенс для банка и медицины |
