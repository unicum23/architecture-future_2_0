# Задание 2. Домены, потоки данных и обоснование

## 1. Разделение на домены

| Домен | Назначение | Почему отдельно от DWH |
|--------|------------|-------------------------|
| **Клиники и операции** | Расписание, ресурсы, клинические операции, интеграция с оборудованием; операционные данные в собственном ODS | Высокая скорость изменений в «поле» не должна упираться в монолит отчётности; новая логика располагается в сервисах и событиях, а не в хранимых процедурах DWH |
| **Финтех** | Продукты банка, платежи, кредиты, лимиты; нормативные и транзакционные данные в ODS финтеха | Финансовый регулятор и релизный цикл банка требуют автономности; интеграция с аналитикой — через контракты данных (события, CDC), а не через доработку ядра DWH |
| **ИИ и клиническая аналитика** | Модели, инференс, оркестрация; доступ к разрешённым медицинским срезам согласно политике | ИИ-компонент обновляется часто; объединение с корпоративной отчётностью повышает риски и задержки; граница с витриной данных зафиксирована политикой (медкарты исключены из BI) |
| **Платформа данных и витрины** | Lakehouse, витрины, KPI, семантический слой, портал самообслуживания | Это **слой потребления** для отчётности, а не место для операционной бизнес-логики доменов; развивается за счёт витрин и пайплайнов, а не процедур внутри устаревшего DWH |
| **Интеграция и партнёрский контур** | API-шлюз, шина событий, адаптеры к фарме и производителям электроники | Партнёры подключаются через стандартизованный контур без внесения изменений напрямую в SQL Server 2008 |
| **Легаси-DWH (переходный)** | Исторические данные, остаточные отчёты; мост (CDC) в платформу данных | Явно выделен как **источник для миграции**, в который новая логика не добавляется |

**Для кого предназначен каждый домен**

- **Клиника:** домен «Клиники и операции» + при необходимости ИИ по контракту данных; аналитика по KPI — через «Платформу данных», без сырых медкарт в витрине (согласно политике компании).
- **Финтех:** домен «Финтех» + потоки в витрины для управленческой и продуктовой аналитики.
- **ИИ:** домен «ИИ» с выделенным хранилищем артефактов; источники данных — по согласованным контрактам из ODS клиник, не из BI-витрины.
- **Будущие партнёры (фарма, электроника):** домен «Интеграция и партнёрский контур» как единая точка подключения каталогов, заказов, лимитов и событий с последующей маршрутизацией в финтех и клиники.

## 2. Логика разделения

1. **Разные темпы изменений:** клиника, банк и ИИ имеют различные релизные циклы и регуляторные рамки; использование общего DWH как площадки для новой логики выравнивает всех по самому медленному участнику и замедляет вывод продуктов.
2. **Разные модели данных:** финансовые проводки, операционные сущности клиники и признаки для моделей не укладываются в единую универсальную схему; доменные ODS и контракты событий снимают необходимость концентрировать всё в одном физическом узле.
3. **Снижение связности:** новые финтех-сервисы и партнёрские сценарии подключаются через шину и API; платформа данных **подписывается** на события и реплики, не требуя изменений ядра DWH.
4. **Безопасность и комплаенс:** граница между клиническими данными для ИИ и агрегатами для отчётности управляется политиками и раздельными потоками на DFD, а не единой «общей таблицей».

---

## 3. Преимущества для бизнеса

| Эффект | Как достигается |
|--------|------------------|
| **Ускорение вывода продуктов** | Команды финтеха и ИИ выпускают функциональность в своих доменах; аналитика потребляет стабильные контракты (события, витрины), не блокируя SQL/DWH-релизы |
| **Снижение зависимости от DWH** | Новая логика не концентрируется в хранимых процедурах и функциях монолита; DWH остаётся источником исторических данных на период миграции, рост обеспечивается lakehouse и доменными пайплайнами |
| **Независимое развитие направлений** | Раздельные ODS, выделенные команды владельцев данных, интеграция через шину и платформу данных |
| **Масштабирование под партнёров** | Фарма и электроника подключаются к интеграционному контуру без изменений схемы центрального хранилища |
| **Предсказуемая отчётность** | Платформа данных формирует витрины и KPI из потоков и CDC, снимая ad-hoc нагрузку с операционных систем и легаси-DWH |

## 4. Связь DFD с бизнес-сценариями

- **Интеграция нового финтех-сервиса:** потоки **P2 → D_Ev → P_Data**; сервис публикует события, витрины обновляются по конвейеру без доработки DWH.
- **ИИ для анализа медицинских данных:** поток **D_Clin ⇢ P_AI** по контракту и политике; результаты могут возвращаться в операционный контур (**P_AI ..> P_Clin**); витрина отчётности (**P_Data / D_LH**) не содержит сырые медкарты.
- **Партнёры:** **E_Pharma / E_Dev → P_Int** с последующей маршрутизацией в финтех и клиники и публикацией в шину для аналитики.
